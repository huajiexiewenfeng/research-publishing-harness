# X Article 空草稿身份恢复：最小修复规格

## 目标与范围

恢复第 5 篇文章的现有草稿 `https://x.com/compose/articles/edit/2095427204960415746`，继续原内容、原执行及其仍有效的授权。不得重新创建草稿、篡改既有报告、跳过核验或点击 Preview/Publish。仅覆盖新建空草稿的身份捕获与恢复，不新增通用恢复框架。

## 已核实原因

- 提取器原先拒绝空标题；该行已修复，有失败转通过测试。
- Host 的 `assertPageIdentity` 无条件要求标题等于母稿标题、命令 Draft ID 等于页面 Draft ID、前一观察也是同一编辑器。创建命令的 Draft ID 本来为空，前一页面本来是列表，故新草稿不能满足这些条件。
- 创建结果不确定会进入 `draft_identity_unknown`。状态机允许转到 `draft_created`，但现有 next/resume/recover 没有实现这一恢复路径。

## 方案选择

1. **采用：在现有 resume-editor/命令循环中补空草稿恢复。** 显式传入已知 Draft URL，发出只读核验命令，核验成功后绑定并继续现有流程。保留审计链，改动集中。
2. 不采用：创建新执行或新草稿。容易重复，且不能修复当前执行。
3. 不采用：直接改状态文件或重写旧成功报告。无法形成可信恢复证据。

## 行为约束

- 恢复入口仅接受新草稿模式、`draft_identity_unknown`、零发布命令、没有待执行命令的执行。要求原创建命令及其 uncertain 报告真实存在。
- 目标 URL 必须是精确的 X 编辑器路径；本次只使用上面的已知 URL。URL 是待核验目标，不是成功证据；执行期间不得换目标。
- 复用现有 next → claim → 只读观察 → report。核对目标账号、URL/Draft ID、空标题、语义空正文、无封面/正文图片、无未知内容及已保存状态。X 的单个空占位段落视为语义空，不把任意非空段落忽略。
- 只有成功的恢复观察才能走已有 `draft_identity_unknown → draft_created → materialization_reconciling`，同步检查点并继续正常的标题填写和正文导入；不能再次下发 create。
- 创建命令的首次观察允许从已核验的列表进入空编辑器；恢复观察允许从旧列表证据进入明确目标的空编辑器。其余命令保留严格身份约束。标题填写前允许空标题，填写后的观察必须匹配批准标题。
- 账号、URL、内容、报告或检查点不一致即停止，保留原草稿和原记录。重复恢复调用不得重复绑定或产生新的浏览器写入。
- 保留原阶段起点和耗时提醒。恢复不能续期授权；若写入权限已经过期，先完成允许的只读核验，再明确请求必要的续期确认。

## 验证与交付

先补失败回归测试，再做最小实现：正常创建空草稿观察、同一草稿恢复、拒绝错账号/错 URL/非空内容/缺失创建证据/重复写入，验证原标题导入和媒体核验不退化。部署仅包含本修复所需文件，不覆盖其他未提交修改或记忆路由更新。

通过后在真实原草稿验证绑定，并在授权仍有效时继续标题、正文、1 张封面与 7 张标题后正文图，最终停于 `draft_reconciled`。测试通过不等于草稿已填充完成；分别报告真实进度。

## 规格自检

无待定项；恢复仅限空草稿，不接管非空草稿；授权不扩大；所有浏览器写入仍经原命令循环；不重写旧报告、不重建文章。
