# X Article `Edit media` Apply 事务设计

## 问题

Chrome 文件选择成功后，X Article 会打开 `Edit media` 对话框，先异步加载图片，再要求点击 `Apply`。当前 Host 在 `setFiles` 后直接观察编辑器，导致对话框尚未提交时被误判为 `x_media_effect_absent`。

## 目标

- 在同一个已 claim 的媒体命令内完成：文件选择、等待 `Edit media`、等待图片加载、点击 `Apply`、等待对话框关闭、页面与自动保存核验。
- 封面和正文图片复用同一媒体编辑器事务。
- 兼容无需媒体编辑器、文件选择后直接落图的 X 页面行为。
- 允许同一素材的受控重试接管前一次尚未 Apply 的媒体对话框。

## 边界

- 只识别唯一可见、名称严格为 `Edit media` 的对话框。
- 只点击该对话框内唯一可见且可用、名称严格为 `Apply` 的按钮。
- 若对话框存在但无法稳定加载、Apply 不唯一或无法关闭，结果必须是不确定或失败，不能声称上传成功。
- 不触碰 Preview、Publish、标题、正文或非当前媒体命令。

## 验证

- 共享层测试覆盖加载完成后 Apply、无对话框直达、对话框无法完成三种结果。
- 封面与正文 Host 测试证明 Apply 发生在页面媒体证据读取之前。
- 聚焦 Host 测试、完整项目检查、部署哈希核对后才恢复真实草稿。
